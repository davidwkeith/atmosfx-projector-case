# Phone Fit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fit the projected picture onto pumpkins, an inflatable or a window from a phone: regions of the video mapped to four corners each, aligned against each face's full reach, saved as named fits.

**Architecture:** A fit is a setting (`fits`, JSON in settings.json, so Backup/Restore carry it). The player applies the active fit as an mpv user shader on the GPU (`glsl-shaders`), with per-region 3x3 homographies passed as shader parameters, which also does the mirror. Setup mode pauses the show and draws an ASS overlay (`osd-overlay`): the face-reach outline (a low-res union mask the Pi computes per clip with a second, niced mpv) or a test grid, warped through the fit. The phone's Setup screen drags corners and previews with CSS `matrix3d`.

**Tech Stack:** Node 20 ES modules, mpv 0.40 (Debian trixie) over JSON IPC, GLSL user shaders, ASS drawing, plain ES modules in the browser, vitest.

**Spec:** `docs/superpowers/specs/2026-10-16-phone-fit-design.md`

## Global Constraints

- Pi 3 is the baseline; hardware H.264 decode stays on (`hwdec=auto-safe`) whenever a fit is active.
- No ffmpeg on the image: every video operation is mpv (`pi/src/poster.js` pattern: `nice -n 19`, one job at a time).
- Nothing user-typed reaches mpv: shader text, shader opts and ASS are generated by the service from validated numbers.
- Web page: plain ES modules, no build step, no CDN, CSP `default-src 'self'; img-src 'self' data:; style-src 'self'` (set `el.style.*` from JS, never `style=` attributes or inline `<style>`).
- Every screen has a help page (`pi/test/help.test.js`); guides use the `public/markdown.js` subset and are listed in `pi/docs/index.md` and the README.
- While DMX is in control, setup is unavailable and says why.
- All coordinates are normalised 0..1, origin top-left, y down: `src` in the video frame, `dst` on the output.
- `MAX_REGIONS = 4`, `MAX_FITS = 20`, fit name 1..40 characters.
- Tests: `cd pi && npx vitest run`, outside Claude Code's sandbox.
- One repo version: if a task ships to the Pi, bump `pi/package.json` only at release time, not in these tasks.

## Review Focus

- The phone locks or walks away mid-setup: the overlay and pause must not stay on the show. Setup ends 5 minutes after the last setup request (Task 7 test `setup ends after 5 idle minutes`).
- A corner dragged across another (a bow-tie or concave quad): rejected by `parseFits` and reverted on the phone to the last valid shape (Task 1 test `rejects a non-convex quad`, Task 9 drag test).
- mpv restarts during the show or setup (crash, display reconnect, args change): the active fit comes back on `ready` (Task 5 test `reapplies the fit after mpv restarts`).
- The schedule, Matter or DMX turns the show off or takes over during setup: setup ends and the saved fit stays (Task 7 test `power off or DMX ends setup without saving`).
- An install upgraded with Mirror on, or a backup restored from before fits existed: the default fit carries `mirror: true` (Task 4 test `migrates the old mirror setting`).

- [ ] **Step 3: Implement `pi/src/fit-math.js`**

`rectToQuad`: normalise the point into the unit square (`u = (x - src.x) / src.w`, `v = (y - src.y) / src.h`), then use Heckbert's closed-form square-to-quad map. Compose the two into one 3x3:

```
dx1 = x1 - x2, dx2 = x3 - x2, dy1 = y1 - y2, dy2 = y3 - y2   (corners 0..3 = TL, TR, BR, BL)
sx = x0 - x1 + x2 - x3, sy = y0 - y1 + y2 - y3
den = dx1*dy2 - dx2*dy1
g = (sx*dy2 - dx2*sy) / den,  h = (dx1*sy - sx*dy1) / den   (both 0 when sx = sy = 0: affine)
a = x1 - x0 + g*x1, b = x3 - x0 + h*x3, c = x0
d = y1 - y0 + g*y1, e = y3 - y0 + h*y3, f = y0
square->quad = [a, b, c, d, e, f, g, h, 1]   (u along TL->TR, v along TL->BL)
```

`parseFits` messages: "active must name one of the fits", "fit name must be 1 to 40 characters", `fit "X" is listed twice`, "a fit needs 1 to 4 regions", "src must be inside the video (0 to 1)", "corners must be between -1 and 2" (corners may go a little off-screen when the projector overshoots the target), "corners must make a convex shape (a corner crossed another)", "at most 20 fits". Copy only known keys (`name`, `mirror`, `regions[].src.{x,y,w,h}`, `regions[].dst`), so the output equals the input for valid data. `src.w`/`src.h` must be at least 0.01.

`cssMatrix3d(m, w, h)`: the page shows each region as the whole poster at stage size (`w` x `h` px), clipped to its `src` with `clip-path: inset(...)` and transformed by `cssMatrix3d(rectToQuad(src, dst), w, h)`. So the px-space matrix is `S·m·S⁻¹` with `S = diag(w, h, 1)`, and its `[a b c; d e f; g h i]` goes into CSS's column-major 4x4 as `matrix3d(a, d, 0, g,  b, e, 0, h,  0, 0, 1, 0,  c, f, 0, i)` (with `transform-origin: 0 0`).

In `pi/src/web.js:35`, add `if (path === "/fit-math.js") return [here("./fit-math.js"), TYPES.js];`.

- [ ] **Step 3: Implement `pi/src/fit-shader.js`**

PARAM blocks (all `//!TYPE float`, so one shader text covers every fit), then:

```glsl
//!HOOK OUTPUT
//!BIND HOOKED
//!DESC videofx fit
vec4 region(vec2 p, mat3 h, vec4 s) {           // s = (x, y, w, h)
  vec3 q = vec3(p, 1.0) * h;                     // row-major params: p * transpose
  if (q.z <= 0.0) return vec4(-1.0);
  vec2 t = q.xy / q.z;
  if (any(lessThan(t, s.xy)) || any(greaterThan(t, s.xy + s.zw))) return vec4(-1.0);
  return HOOKED_tex(t);
}
vec4 hook() {
  vec2 p = HOOKED_pos;
  if (mirror > 0.5) p.x = 1.0 - p.x;
  vec4 c;
  // one block per region i < 4, generated:
  if (n > 0.5) { c = region(p, mat3(h0_0, h0_1, h0_2, h0_3, h0_4, h0_5, h0_6, h0_7, h0_8), vec4(s0_x, s0_y, s0_w, s0_h)); if (c.a >= 0.0) return c; }
  ...
  return vec4(0.0, 0.0, 0.0, 1.0);
}
```

GLSL `mat3(...)` fills columns, so `vec3(p,1) * h` with the row-major list gives the row-major product. The spike (Task 3) confirms the orientation on the Pi. If `HOOKED_pos` turns out y-up there, flip `p.y` and `t.y` in the generator, not in the maths.

  - `overlayAss(fit: Fit, { mode: "reach"|"grid", reach?: {w,h,mask: Uint8Array} }) -> string`: ASS events. Region outlines in yellow `&H00FFFF&`, reach in green `&H00FF00&`, grid in white. Each corner gets a 40 px circle and its number (1 TL, 2 TR, 3 BR, 4 BL) with the region letter (A, B, C, D). It can be called repeatedly while on (each call a new preview). Off: `osd-overlay` with `format: "none"`, unpause, and re-apply the saved fit (`content().fit`).
  - `player.setupPlay(playing: boolean)`: unpauses or pauses without leaving setup (the overlay stays).
  - The player ends setup on its own when: 5 minutes pass with no `setSetup` or `setupPlay` call (`SETUP_IDLE_MS = 300000`, my call), `setOn(false)`, a mpv `down`, or `failed`. It emits `"setup"` with `{on: false, why}`.
