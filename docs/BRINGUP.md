# Hardware bring-up checklist

Everything below has only been tested in software. Work through it on the bench before the case goes outside, and record results in the design log. Each line has a pass criterion. If one fails, the "if not" column says what changes.

## Verified so far

- **Projector EDID (2026-10-05, read on a MacBook with `ioreg -l | grep EDID`, decoded by hand).** The projector presents a generic STK "S2-TEK TV" EDID (product 0x531A, block dated 2014, serial SN-000000001), so the identity is the HDMI SoC's, not the projector maker's. Native mode 1080p60 (VIC 16); also 1080p24/30/50, 1080i50/60, 720p50/60 and the SD modes. 8-bit RGB and YCbCr only, max TMDS clock 150 MHz: no 4K, no HDR, no deep colour. Audio: 2-channel LPCM at 32/44.1/48 kHz (unused; audio goes to the DigiAMP+). The feature byte claims DPMS standby, suspend and active-off, which is what the `hdmi-off` power mode relies on. The HDMI vendor block carries CEC physical address 2.0.0.0 with Supports_AI set, so the input is real HDMI rather than DVI-over-HDMI. **That does not prove CEC works**: the address field is mandatory for every HDMI sink and 2014-era STK projectors often omit CEC, so row 9 still decides. Hot-plug detect was reported active, so the Pi's HDMI wait (row 9a) should see it. Set the Pi to 1080p60 and nothing higher. The EDID carries no geometry (its 93 x 53 cm screen size is a placeholder), so rows 2 and 3 are unchanged.
- Apple's [HDMI-CEC Support on Mac](https://support.apple.com/en-us/108928) page says some Macs do CEC: Mac Studio (M4 Max or M3 Ultra, 2025), MacBook Pro (M3 Pro/Max or later), Mac mini (M4 or M4 Pro), and any Apple silicon Mac on macOS 14.4+ through Apple's USB-C Digital AV Multiport Adapter or the Belkin Connect USB-C to HDMI Adapter. The owner's Mac Studio (M3 Ultra, 2025) qualifies. macOS only syncs display wake/sleep with the Mac and exposes no way to send arbitrary CEC commands, so row 2b is a pre-check; row 9 on the Pi still decides.
